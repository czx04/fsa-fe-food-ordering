CHƯƠNG 2: PHÂN TÍCH YÊU CẦU BÀI TOÁN2.1. Đặc tả bài toán tổng thể của hệ thốngĐoạn 1 (Mục tiêu nền tảng): Xây dựng giải pháp web quản lý và đặt món ăn toàn diện, hỗ trợ người dùng tìm kiếm món ăn, tạo giỏ hàng, đặt hàng, thanh toán và giúp nhà hàng quản lý thực đơn, tiếp nhận và xử lý đơn tức thời.Đoạn 2 (Luồng nghiệp vụ khép kín): Chu trình End-to-End: Khách hàng duyệt menu $\rightarrow$ Chọn món $\rightarrow$ Áp mã giảm giá/Tính phí vận chuyển $\rightarrow$ Checkout tạo đơn $\rightarrow$ Nhà hàng tiếp nhận và cập nhật trạng thái $\rightarrow$ Giao hàng $\rightarrow$ Người dùng đánh giá chất lượng món.Đoạn 3 (Mục tiêu và phạm vi báo cáo): Xác định phạm vi trọng tâm báo cáo đi sâu vào phân tích, thiết kế và hiện thực hóa phân hệ Giỏ hàng & Xử lý đơn hàng do sinh viên trực tiếp đảm trách. 2.2. Yêu cầu chức năng và phi chức năngDẫn dắt & Chèn Sơ đồ Ca sử dụng:Hình 2.1: Sơ đồ ca sử dụng (Use Case Diagram) tổng thể hệ thống (Thể hiện các tác nhân Customer, Merchant, Admin/System và các nhóm use case chính kèm liên kết <<include>>, <<extend>>). Đoạn 2 (Danh mục yêu cầu chức năng - FR): Liệt kê các yêu cầu cụ thể (thêm/sửa/xóa giỏ hàng, quy tắc giỏ hàng thuộc một nhà hàng duy nhất, kiểm tra voucher máy chủ, tính phí ship, tạo snapshot dữ liệu, hủy đơn, đặt lại đơn). Đoạn 3 (Danh mục yêu cầu phi chức năng - NFR): Tiêu chuẩn định lượng: hiệu năng API (latency p95 < 200ms), tính toàn vẹn dữ liệu (ACID/Snapshot), chống tạo trùng đơn (Idempotency), độ trễ truyền thông realtime (< 1s), bảo mật token JWT và kiểm tra chặt chẽ dữ liệu đầu vào. 2.3. CHƯƠNG 3: THIẾT KẾ VÀ CÀI ĐẶT HỆ THỐNG3.1. Cơ sở công nghệ và giải pháp kỹ thuậtĐoạn 1 (Công nghệ ngăn xếp & Lý do lựa chọn): Phân tích lý do lựa chọn tech stack: Node.js/Express (xử lý I/O bất đồng bộ tốt, phù hợp API thời gian thực), MongoDB/Mongoose (linh hoạt trong lưu trữ snapshot đơn hàng không bị thay đổi theo menu), Socket.IO (hỗ trợ truyền thông hai chiều, quản lý room theo đơn hàng/nhà hàng dễ dàng), React/TypeScript (an toàn kiểu dữ liệu, tái sử dụng component). 3.2. Kiến trúc giải pháp và thiết kế hệ thốngĐoạn 1 (Kiến trúc phân tầng tổng thể): Giới thiệu mô hình phân tầng rõ ràng: Client (Web App) $\rightarrow$ API Gateway/Router $\rightarrow$ Controller $\rightarrow$ Service (Business Logic) $\rightarrow$ Model/Repository $\rightarrow$ Cơ sở dữ liệu. Dẫn dắt & Chèn Hình Kiến trúc:Hình 3.1: Sơ đồ kiến trúc phân tầng của hệ thống (Thể hiện rõ các lớp logic và kênh song song giữa REST API và Socket.IO Server).Đoạn 2 (Thiết kế Cơ sở dữ liệu): Mô tả các thực thể dữ liệu trọng tâm: Cart, CartItem, Order, Coupon, Restaurant, MenuItem; nguyên lý lưu snapshot thông tin khách hàng, nhà hàng, đơn giá tại thời điểm checkout. Dẫn dắt & Chèn Lược đồ ERD:Hình 3.2: Lược đồ quan hệ thực thể (ERD) phân hệ Giỏ hàng và Đơn hàng (Chi tiết các thuộc tính khóa PK, FK, quan hệ 1-N, N-N, các kiểu dữ liệu và trường snapshot). 3.3. Hiện thực hóa các tính năng cốt lõiĐoạn 1 (Hiện thực tính năng Giỏ hàng - Cart Feature): Quy tắc giới hạn một nhà hàng (trả mã lỗi 409 khi xung đột), logic cập nhật số lượng, xóa món, tự động tính toán lại subtotal và kiểm tra điều kiện mã giảm giá trên máy chủ. Đoạn 2 (Hiện thực tính năng Xử lý Đơn hàng & Realtime - Order Management Feature): Luồng tạo đơn checkout (khóa giao dịch, sao lưu snapshot dữ liệu, xóa giỏ hàng), chuyển đổi trạng thái đơn phía nhà hàng (State Machine) và cơ chế phát sự kiện order:updated qua Socket.IO tới các room tương ứng. Kiểm thử hệ thốngĐoạn 1 (Kiểm thử chức năng giao diện - Manual Test): Thực hiện kiểm thử thủ công trên trình duyệt các ca sử dụng người dùng: thao tác thêm/sửa/xóa giỏ hàng, thông báo xung đột khác nhà hàng, áp dụng voucher hợp lệ/không hợp lệ, thao tác checkout.Đoạn 2 (Kiểm thử API Endpoint): Sử dụng Postman để kiểm thử các endpoint /api/cart, /api/orders/checkout, kiểm tra tính đúng đắn của mã trạng thái HTTP (200, 201, 400, 404, 409), kiểm tra phân quyền truy cập và đo đạc thời gian phản hồi API (đạt mục tiêu < 200ms). Đoạn 3 (Kiểm thử kết nối Realtime & Ngoại lệ): Kiểm thử kênh WebSocket: kiểm tra việc nhận sự kiện tức thời khi trạng thái đơn đổi từ pending sang confirmed, kiểm tra cơ chế ngắt kết nối mạng và tự động kết nối lại (reconnect) kết hợp gọi REST API để đồng bộ dữ liệu. 4.2. Quy trình thiết lập và triển khai hệ thốngĐoạn 1 (Chuẩn bị môi trường & Cấu hình): Đặc tả môi trường thực thi (Node.js, Docker, MongoDB), quản lý an toàn biến môi trường (.env chứa cấu hình kết nối CSDL, khóa bí mật JWT, cổng Socket, URL client). Đoạn 2 (Đóng gói và Triển khai - Build & Deploy): Đóng gói ứng dụng bằng Docker/Docker Compose; quy trình tự động hóa CI/CD qua GitHub Actions để lint, build và phát hành các container dịch vụ. Dẫn dắt & Chèn Hình Triển khai:Hình 4.1: Sơ đồ quy trình đóng gói và triển khai hệ thống (Minh họa pipeline: Git Push $\rightarrow$ GitHub Actions Build/Lint $\rightarrow$ Docker Registry/Compose $\rightarrow$ Server Deployment). CHƯƠNG 5: KẾT QUẢ ĐẠT ĐƯỢC VÀ HƯỚNG PHÁT TRIỂN5.1. Kết quả đạt đượcĐoạn 1 (Mức độ hoàn thành chức năng): Tổng kết tỷ lệ hoàn thành các yêu cầu đặt ra: xây dựng trọn vẹn luồng Cart $\rightarrow$ Checkout $\rightarrow$ Order $\rightarrow$ Đồng bộ trạng thái theo thời gian thực; hệ thống hoạt động ổn định và kiểm thử đạt yêu cầu. Đoạn 2 (Kiến thức và kỹ năng thu thập được): Nâng cao năng lực chuyên môn về lập trình Fullstack (Node.js, React/TypeScript, WebSocket, MongoDB), hiểu sâu về thiết kế CSDL và giao dịch snapshot; tiếp thu tác phong làm việc chuẩn doanh nghiệp theo mô hình Agile/Scrum và văn hóa giao tiếp kỹ thuật. 5.2. Hạn chế và hướng phát triển trong tương laiĐoạn 1 (Hạn chế tồn đọng): Thừa nhận các điểm cần tối ưu: chưa xây dựng phân hệ quản lý kho tồn kho chi tiết (Inventory Service), chưa gom cụm Socket Server bằng Redis Adapter khi mở rộng tải ngang, và thao tác tạo đơn - xóa giỏ hàng cần bọc trong MongoDB Multi-document Transaction hoàn chỉnh. Đoạn 2 (Hướng phát triển tiếp theo): Kế hoạch nâng cấp: tích hợp Redis In-memory Caching để giảm tải truy vấn giỏ hàng/thực đơn, áp dụng Message Queue (RabbitMQ/Kafka) để xử lý các tác vụ bất đồng bộ nặng (gửi mail, thông báo tài xế), và xây dựng service điều phối tài xế độc lập. Dẫn dắt & Chèn Hình Kiến trúc tương lai:Hình 5.1: Sơ đồ kiến trúc mở rộng hệ thống trong tương lai (Mô hình bổ sung Redis Caching, RabbitMQ Message Broker và Driver Microservice).
